1. INTRODUCTION                                                   *relay-intro*

relay.nvim pastes code into the prompt of a running Claude Code, Codex or
GitHub Copilot CLI session. Press <leader>aq on a selection (or a line) for a
menu: add it to the queue, add it with context, send it to your agent, send
the whole queue, or view the queue. Sends ask for an optional prompt, which
goes at the top.

Saved code is sent as a mention, `@path#L10-20`, so the agent reads exactly
those lines. Every agent gets the same message. Code that only exists in
Neovim (unsaved changes, buffers without a file, code deleted after it was
queued) is sent inline in a fenced block. See |relay-format|.

Sessions are looked up live on every send (nothing polls in the background).
They can run in a Neovim |terminal| (this or another instance), tmux, zellij
(before 0.44 by moving the focus to the agent's pane), kitty with remote
control, or WezTerm. Sessions that can't be typed into are still listed;
choosing one copies the message to the clipboard.

Requires Neovim 0.10+. Linux has full support; elsewhere sessions in Neovim
terminals, tmux and WezTerm work.

2. SETUP                                                          *relay-setup*

With lazy.nvim: >lua
    { "bnamayandev/relay.nvim", opts = {} }
<
Defaults: >lua
    require("relay").setup({
      keymaps = {
        menu = "<leader>aq",     -- normal + visual: action menu
        open = "<leader>aa",     -- visual: overlay
        add = false,             -- visual: queue the selection directly
        queue = false,           -- normal: open the queue directly
        send = "<leader>as",     -- normal: send the queue
        file = "<leader>af",     -- normal: queue the current file
        note = "<leader>an",     -- normal: context of snippet under cursor
        clear = "<leader>ax",    -- normal: clear the queue
        target = "<leader>at",   -- normal: pin / unpin a session
        sessions = "<leader>aj", -- normal: jump to a session
      },
      format = "auto",
      submit = true,
      focus = "auto",
      clear_on_send = true,
      diagnostics = false,
      clipboard_fallback = true,
      submit_delay = 80,
      claude_dir = nil,
      agents = { claude = true, codex = true, copilot = true },
      launch = {
        split = "right",
        size = 0.35,
        cmd = { claude = { "claude" }, codex = { "codex" },
                copilot = { "copilot" } },
      },
      picker = "select",
      backends = { nvim = true, tmux = true, zellij = true, kitty = true,
                   wezterm = true },
      signs = true,
      virtual_text = true,
      ui = { border = "rounded", width = 0.6, max_preview = 15, icon = "󰚩" },
    })
<
                                                              *relay-keymaps*
keymaps         Table of keys, or `false` for none. Set a single entry to
                `false` to skip it.

                                                               *relay-format*
format          "ref": `@path#L10-20` mention. "inline": the code in a fenced
                block. "auto": ref when the file is saved on disk, inline
                otherwise. Can be overridden per snippet.

submit          Press Enter in the agent after pasting. false: the text
                waits in the agent's prompt.

                                                                *relay-focus*
focus           Switch to the agent's pane/window after sending. "auto" does
                so only when not submitting (you'll want to continue typing
                there).

clear_on_send   Empty the queue after it was delivered. |:Relay| restore
                brings it back.

diagnostics     Include LSP diagnostics of the snippet's lines by default.

clipboard_fallback
                Copy the message when it can't be delivered.

submit_delay    Milliseconds between the paste and Enter.

claude_dir      Claude Code's config directory (for the session registry).
                Defaults to $CLAUDE_CONFIG_DIR or ~/.claude.

                                                               *relay-agents*
agents          Which agents' sessions to list: `claude`, `codex`,
                `copilot`. Set one to `false` to ignore its sessions.

                                                               *relay-launch*
launch          Offer to start an agent while none is open in this Neovim
                (see |relay-start|), or `false` to never offer it.
                `split`: where its terminal opens, "right", "left", "above",
                "below" or "tab". `size`: the split's width (height for
                "above"/"below"), a fraction of the editor or, when >= 1,
                columns (lines). `cmd`: the command for each agent, a list or
                a shell string; set one to `false` to not offer it, e.g.
                `copilot = { "gh", "copilot" }` or `claude = false`.

                                                               *relay-picker*
picker          The picker for choosing a session or an agent to start.
                "select": |vim.ui.select()|, or whatever your config replaced
                it with. "snacks", "telescope", "fzf-lua", "mini.pick": that
                picker (vim.ui.select when it isn't installed). Or a function
                called like |vim.ui.select()|: `function(items, opts,
                on_choice)`, where `opts.kind` is "relay.session" or
                "relay.agent" and `opts.format_item(item, true)` returns
                highlighted chunks for the entries that start an agent.

backends        Turn off support for a terminal. Its sessions are then listed
                as clipboard-only.

signs, virtual_text
                Mark queued code in the sign column / after its first line.

==============================================================================
MENU                                                               *relay-menu*

<leader>aq opens a menu at the cursor for the visual selection, or for the
cursor line in normal mode (`:Relay` does the same):

  a  Add to queue
  A  Add file           the whole file, as its path with no line numbers
  c  Add with context   (Edit context when it's already queued)
  s  Send line          or Send selection: just this, after an optional prompt
  S  Send queue (n)     the whole queue, after an optional prompt
  v  View queue (n)     delete entries with x

Also 1-6, or j/k and <CR>. A snippet's context is sent in front of it as
"context: @path#L10". The prompt goes before everything else; leave it empty
to send without one.

==============================================================================
3. OVERLAY                                                      *relay-overlay*

Opened from visual mode with <leader>aa (or `:'<,'>Relay`). Shows the
selection and a note box in insert mode.

  <CR>          send this snippet with its context
  <C-s>         send and press Enter in the agent
  <Tab>         add to the queue
  <C-a>         add to the queue, then send the whole queue
  <C-t>         send, choosing the session (ignores a pinned one)
  <C-f>         toggle @mention / inline code
  <C-d>         toggle LSP diagnostics
  <C-e> <C-y>   scroll the preview
  <C-j>         new line in the context (insert mode)
  <C-c>         close; in normal mode also <Esc> and q

==============================================================================
4. QUEUE                                                          *relay-queue*

Queued snippets are tracked with extmarks: their line numbers follow your
edits. When the file is reloaded from disk (e.g. an agent changed it and
'autoread' picked it up), each snippet is found again by its content. If only
its first and last lines survived it is marked "edited outside"; if it's gone
it is marked "gone from file" and sent inline with the text you queued.

Queuing the same lines again updates the existing entry.

Keys in the queue window (<leader>aq in normal mode, or `:Relay`):

  s             send the queue
  S             send, choosing the session
                (both open a prompt box first: type a prompt that goes at
                the top, or just press <CR> to send without one)
  e i a         edit the snippet's context
  x dd          delete the snippet
  u             restore the last deleted snippet(s)
  K J           move up / down
  f             cycle format: auto -> ref -> inline
  D             toggle LSP diagnostics
  p             preview the exact message
  <CR> o        jump to the snippet
  C             clear the queue
  t             pin a session
  ?             list these keys
  q <Esc>       close

5. SESSIONS                                                    *relay-sessions*

On send, Relay reads Claude Code's session registry (~/.claude/sessions) and
scans the process table for `claude`, `codex` and `copilot` processes. They
are recognized by their command line, so the npm installs (a node wrapper that
starts a native binary) count as one session, and `claude -p`, `codex exec`
and `copilot -p` don't count. For each session it finds the
program that owns its terminal: the first ancestor process attached to a
different tty. A session in tmux inside zellij is therefore reached through
tmux, never through the outer layers.

With one session it is used directly. With several, a picker (see
|relay-picker|) lists them, each as name, root directory, branch, then agent: >
    api-refactor  ~/code/api  [main]  ○ claude idle  tmux work:2.1
    relay.nvim  ~/projects/relay.nvim  [main]  · codex  zellij agents/3
    docs  ~/code/docs  [main]  · copilot  kitty window 4
<
Only Claude Code publishes busy/idle. The last used session and those working
on the current project come first. Pin one with <leader>at to skip the picker
until it exits.

Text arrives as a bracketed paste with control characters removed. Claude
shows a multi-line paste as "[Pasted text #1 +N lines]" and resolves the
mentions inside it on submit. Codex gets a space after the message: without
it, a message ending in a mention leaves Codex's file search popup open, and
that popup would take the Enter meant to submit.

zellij older than 0.44 can only type into the focused pane. When one client is
attached to the session, Relay moves its focus through the panes (and tabs)
until the agent's pane is focused, checks that with `zellij action
list-clients`, types, and moves the focus back unless it should stay there
(see |relay-focus|). zellij 0.44+ pastes into the pane without moving focus.

kitty needs `allow_remote_control` and `listen_on` in kitty.conf.

                                                                *relay-start*
The session picker (for sending, pinning and jumping) ends with "New agent…"
(`RelayNewAgent`, in pickers that support highlights: snacks.nvim, telescope).
Choosing it lists the installed agents (see |relay-launch|) to start one in
Neovim. With no session running anywhere they are listed right away instead.
While no session is open in this Neovim, the picker is shown even for a single
session elsewhere. The agent runs in a narrow terminal split on the right, in
the current directory, and the message is sent once it's ready. The session
keeps running afterwards like any other. Pin a session outside Neovim to send
there without the picker.

Startup screens that wait for a key ("trust this folder?", Codex's update
notice) are left for you to answer: Relay waits until they're gone, because
Enter there picks an option such as "No, exit". Claude Code registers itself
once its prompt is up, so `submit` works as usual. Codex and Copilot publish
nothing, so Relay waits for their output to settle and never presses Enter
for that first message. If the agent exits first, the message is copied.

6. COMMANDS                                                    *relay-commands*

                                                                       *:Relay*
:Relay                  Action menu for the cursor line.
:{range}Relay           Action menu for the lines.
:Relay menu             Same.
:{range}Relay open      Same.
:{range}Relay add [context]
                        Queue the lines (with context).
:Relay file [context]   Queue the current file as a whole.
:Relay send [prompt]    Send the queue, with an optional prompt first.
:Relay send! [prompt]   Same, but always choose the session.
:Relay queue            Open the queue.
:Relay clear            Clear the queue.
:Relay restore          Restore the last removed snippet(s).
:Relay preview          Show the message the queue would produce.
:Relay note             Edit the context of the snippet under the cursor.
:Relay target           Pin a session.
:Relay target clear     Unpin.
:Relay sessions         Jump to a running session.

7. LUA API                                                          *relay-api*

  require("relay").menu()           action menu (selection or cursor line)
  require("relay").open()           overlay for the visual selection
  require("relay").add()            queue the visual selection
  require("relay").add_file()       queue the current file
  require("relay").send(opts)       send the queue; opts: `message` (prompt),
                                    `pick`,
                                    `submit`, `focus`, `items`
  require("relay").queue()          open the queue window
  require("relay").clear()          clear the queue
  require("relay").restore()        restore removed snippets
  require("relay").target()         pin a session
  require("relay").unpin()          unpin
  require("relay").sessions()       jump to a session
  require("relay").note()           context of the snippet under the cursor
  require("relay").preview()        preview the message
  require("relay").items()          the queued snippets
  require("relay").count()          number of queued snippets
  require("relay").statusline()     "󰚩 3 → session" or ""

                                                        *RelayQueueChanged*
The `User RelayQueueChanged` autocmd fires when the queue or the pinned
session changes.
